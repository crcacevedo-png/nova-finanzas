# IGSS No. SPS — Shape ("patrones") Analysis

**Database (read-only):** `novavision-finanzas-test_database` (confirmed via mongo_query; this is the live production DB).
**Operations used:** `list_collections`, `count`, `find` only. **No writes, no index creation, nothing persisted to the DB.**

## Method
- Normalization: `value = str(v).strip().upper()`; empty skipped.
- Shape: every run of digits replaced by its length, hyphens kept (e.g. `01-101104-2026-150323` → `2-6-4-6`; `179099569` → `9`; `01-30103-2026038695` → `2-5-10`).
- Order = distinct pair (patient id, normalized SPS) across all 4 sources (patients→id, acreditaciones→paciente_id, evaluaciones→paciente_id, surgeries→patient_id), de-duplicated into one global set.
- Sources: (1) patients referral_institution=="igss": igss_ordenes[].no_sps + legacy igss_no_sps; (2) igss_nog_acreditaciones.no_sps, anulada==true skipped; (3) evaluaciones_oftalmologicas.igss_no_sps for igss patients only; (4) surgeries institution=="IGSS", igss_data.sps, status=="cancelado" skipped (none were cancelado).

## Caveat — 3 surgeries with patient_id = null
Three `surgeries` rows (institution=="IGSS", status "activo") have `patient_id: null`. Per the literal (patient_id, SPS) rule they were counted as `(null, SPS)` orders:
- `01-11504-2026-107175` (value appears nowhere else)
- `01-10124-2026-031995` (value also under patient 94ce0a60 / rec 15956)
- `01-10202-2026-019256` (value also under patient d52c3bc9 / rec EXP-202610-0073)

All three are shape `2-5-4-6`. If null-patient surgeries are EXCLUDED: distinct orders = **144**, distinct values = **143**, shapes = **10** (shape `2-5-4-6` becomes 105 orders / 104 values). Decide per audit intent.
